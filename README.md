# 保险理赔客服 AI 助手 · 练手项目

用 Python 打通「调用大模型 API → 处理异常 → 多轮对话 → 数据持久化」这条链路。
不是产品，是把基础能力跑通。

## 项目结构

```
chatbot.py     多轮对话客服助手（调用 DeepSeek API）
cart.py        购物车系统（字典 + JSON 持久化）
test_cart.py   cart.py 的函数级测试
```

## 1. chatbot.py — 理赔客服助手

**能做什么**

- 多轮对话，记得住上下文
- 信息不全时先反问（险种 / 住院时间 / 是否首次投保），不急着下结论
- 涉及时间的会自己算间隔天数（10 月 1 日投保、11 月 18 日住院 = 48 天）
- 给的是带前提的判断（「若等待期 30 天则…，若 90 天则…」），而不是一句「以审核为准」
- 不承诺赔付结果，统一回复「需提交材料后由理赔审核判定」

**技术点**

- API Key 放在 `.env`，代码里用 `os.getenv()` 读取，不进版本库
- 网络超时 / 401 / 429 分别有兜底话术，程序不崩
- 最多重试 3 次，间隔 1 秒
- 只保留最近 10 轮对话，防止上下文无限增长
- `system prompt` 里注入当天日期，模型才知道「今天」是哪天

## 2. cart.py — 购物车系统

**能做什么**

- 增、删、改、查、清空
- 关掉程序再打开，数据还在（JSON 存储）
- 加同一件商品会累加数量

**技术点**

- 拆成 5 个函数，每个只做一件事，返回提示语而不是直接 print
- 数据以参数传入，不用全局变量
- 主循环只负责「问 → 调 → 打印」
- 第一次运行没有 `cart.json` 时，捕获 `FileNotFoundError` 返回空字典

## 3. test_cart.py

直接 import 函数做验证，不用手动敲菜单：

```
苹果已经加入购物车
苹果数量已经累加到 5
苹果已修改
苹果|单价12|数量5
苹果已删除
购物车是空的
```

## 踩过的坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 多轮对话失效，AI 重复回答旧问题 | 成功分支 `return` 跳过了 `messages.append` | 先存历史再 return |
| 换镜像源后装包失败 | 源不可用 | 退回官方源 |
| `.gitignore` 不生效 | 目录名多了个前导空格 | 重命名目录 |
| 已追踪的文件加进 `.gitignore` 无效 | ignore 只对未追踪文件生效 | `git rm --cached` |
| `import` 购物车就启动菜单 | 顶层有 `while True` | 包进 `if __name__ == "__main__"` |

## 已知局限

- 还没接知识库，回答靠模型自身知识，涉及具体条款只能说「以条款为准」
- 槽位只存在对话历史里，没有结构化存储
- 没有测试集，效果好坏无法量化

下一步：接 RAG 知识库、把槽位单独存成结构、建 100 条测试集跑通过率。
